# Shared song links

The song studio keeps the current configuration in the `song` query parameter. Copy the address or use **Copy song link**. Opening a link restores the controls and generates the song; playback remains a listener action because browsers restrict automatic audio playback. Unrendered edits are shared as the current settings; generate before sharing to preview them.

The payload includes the title and every `ArrangementSettings` field, including nullable melody seed, song seed, instrument IDs/order, disabled instruments, banks/programs, levels, registers, piano voicings, all presence probabilities and occurrence overrides, ending weights and composition controls. It uses compact source-generated JSON, GZip compression and URL-safe base64. It needs no account, browser library or server-side song storage. Settings and title are visible to anyone who has the link; encoding does not make them private.

Links carry schema, composer and playback versions and the SHA-256 of the bundled GeneralUser GS bank. Compatible links reproduce the same written score and render settings. Incompatible versions/banks show an error rather than silently composing a different song. This implementation does **not** host historical composer builds: keep an exported song JSON for durable written-note replay across composer changes. Audio identity is verified within the same renderer/runtime; different audio hardware and runtimes are not a promise of bit-identical playback.

Playback version 1 means the current layered rendering implementation, MeltySynth dependency and 22,050 Hz mono render. Increment it if the renderer, render options or dependency changes audibly. Composer changes use `ArrangementComposer.Version`. When replacing the bundled bank, update the identity in `StudioSongLink`; actual render metadata is checked against it. This supports composition rules R11/R13 without changing musical behaviour or composer version 7.

Edits replace the current browser-history entry rather than adding one per control movement. Visiting another shared link and browser back/forward restores its settings. A malformed link does not fall back to an unrelated default song. A separate melody seed remains null when blank. Older imported written scores cannot be shared as if current settings would regenerate their exact notes; export their song JSON instead.

The decoder bounds both encoded input (24,000 characters) and expanded JSON (256 KiB), validates required metadata and composition settings, and rejects invalid or unsupported payloads. Large configurations may exceed a messaging service's URL limits even below this bound; use settings/song JSON exports in that case. No settings are silently omitted to shorten links.

Validation: 217 tests pass, including full settings round-trips, nullable/explicit melody seeds, 24 layers and up to 100 overrides per layer, unsupported metadata, damaged links, bounded decompression, exact written-score equality and byte-identical WAV rendering. Chromium verification on the Release WebAssembly build opens a 1,055-character link in a fresh browser context with no saved library and confirms identical score JSON and WAV SHA-256. It also checks editing/title/seeds, copying, same-page link navigation, back navigation, invalid-link rejection and mobile overflow. Rebuild the demo and repeat these browser checks when changing routing, the JSON context or the codec; native codec tests alone cannot detect browser-platform API incompatibilities.
