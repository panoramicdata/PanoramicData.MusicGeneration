# PanoramicData.MusicGeneration.SoundFonts

Optional sampled-instrument rendering for scores generated by
`PanoramicData.MusicGeneration`, using MeltySynth 2.4.1 (MIT).

```sh
dotnet add package PanoramicData.MusicGeneration.SoundFonts
```

Supply an SF2 bank whose terms permit your intended use. No bank is bundled in this
package and the adapter performs no network requests.

```csharp
using PanoramicData.MusicGeneration;
using PanoramicData.MusicGeneration.SoundFonts;

var score = SongGenerator.Generate(42, 60, 11025);
var renderer = new SoundFontRenderer(File.ReadAllBytes("my-bank.sf2"), "my-bank");
var result = await renderer.RenderAsync(score);
File.WriteAllBytes("song.wav", result.Song.ToWav());
```

Inspect `renderer.Presets` and set `SoundFontRenderOptions.Parts` to choose bank,
zero-based program and MIDI velocity for each role. Defaults require GM strings,
acoustic bass, piano and a standard percussion kit. Missing presets fail explicitly.
The input bank limit is 64 MiB; output rates are 16,000–96,000 Hz, default 22,050.

The returned song retains the written notes and section boundaries, adds raw stems
for mute/solo, and supplies one full-mix normalisation gain. Output is mono, with
effects disabled and release tails clipped at the requested duration. The metadata
records the bank SHA-256, renderer version, settings and instrument assignments.

Native .NET and browser WebAssembly use the same managed adapter. Repeatability is
scoped to the bank, renderer, settings and runtime; cross-platform bit-identical PCM
is not promised. The procedural core and its golden output remain unchanged.

See [API/design, asset terms and resource budgets](https://github.com/panoramicdata/PanoramicData.MusicGeneration/blob/main/docs/SOUNDFONTS.md)
and the [same-score demonstration](https://music.panoramicdata.com/song?form=sections&sound=soundfont).

## Live keyboard notes

`renderer.CreateKeyboardVoice(program, midi, velocity, sampleRate)` starts a bank-0 note. Call `Render(sampleCount)` sequentially for small mono PCM blocks, then `Release()` when the key is lifted and keep rendering its release tail. Release is idempotent and uses the SF2 instrument's own note-off envelope; no per-block peak normalisation is applied. Each voice is independent, including repeated overlapping pitches. The caller owns scheduling, mixing and voice cleanup. The demo keyboard uses this path for held notes and piano damping; score rendering remains unchanged.
